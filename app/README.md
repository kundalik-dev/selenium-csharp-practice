# Todo practice API

Standalone JavaScript application using Express and SQLite. Copy this folder
anywhere to run it; it does not depend on .NET, Selenium, or the parent repository.

## Run

Requires Node.js 24 or newer.

```sh
cd app
npm install
npm start
```

If your terminal is already inside this folder, skip `cd app`.
Base URL: **http://localhost:3000**. Stop with Ctrl+C.
Use `npm run dev` for automatic restart after source edits and `npm test` for integration tests.

The database is created automatically at `data/todos.sqlite`. Todos survive
restarts. The two sample todos are inserted only when the first migration runs;
deleting every todo does not cause them to return on restart.

The app uses Node's built-in `node:sqlite` driver, so no database service or native
npm driver is needed. Node 24 may print an experimental SQLite warning.
See the [Node SQLite documentation](https://nodejs.org/api/sqlite.html).

## Organization

```text
app/
  server.js                         # Starts HTTP server; closes database on shutdown
  src/
    app.js                          # Express setup and feature router registration
    config.js                       # Environment configuration
    database/
      index.js                      # SQLite connection and migration runner
      migrations/
        001_create_todos.sql        # Todo schema and one-time sample data
    middleware/
      errors.js                     # Shared JSON errors and unmatched routes
    modules/
      todos/
        todo.routes.js              # URLs, HTTP methods, validation middleware
        todo.validation.js          # Request validation and normalization
        todo.controller.js          # HTTP responses and status codes
        todo.repository.js          # Parameterized SQL and row conversion
  test/
    todos.test.js                   # HTTP integration and persistence tests
  data/                             # Local SQLite files, ignored by Git
  .env.example
  package.json
```

Request flow: router → validation → controller → repository → SQLite.
Each feature owns its code. Shared infrastructure lives outside feature folders.
Express routers provide the module boundaries; see [Express routing](https://expressjs.com/en/guide/routing/).

## Configuration

Defaults work without configuration. Optionally copy `.env.example` to `.env`:

```powershell
Copy-Item .env.example .env
```

| Variable      | Default           | Purpose                                       |
| ------------- | ----------------- | --------------------------------------------- |
| PORT          | 3000              | HTTP port                                     |
| HOST          | 127.0.0.1         | Listen address                                |
| DATABASE_PATH | data/todos.sqlite | SQLite file path, relative to this app folder |

The app loads `.env` on startup. Existing environment variables take precedence.
Database paths resolve relative to this folder even when you launch from another directory.

## Routes

| Method | Route        | Success response                      |
| ------ | ------------ | ------------------------------------- |
| GET    | `/`          | 200: API status message               |
| GET    | `/todos`     | 200: array of todos, ordered by ID    |
| GET    | `/todos/:id` | 200: one todo                         |
| POST   | `/todos`     | 201: created todo and Location header |
| PUT    | `/todos/:id` | 200: replaced todo                    |
| DELETE | `/todos/:id` | 204: no response body                 |

For POST and PUT, use `Content-Type: application/json`:

```json
{
  "title": "Practice with RestSharp",
  "completed": false
}
```

`title` is required and must be a non-empty string; surrounding whitespace is trimmed.
`completed` is optional and defaults to false, including on PUT. If supplied, it
must be a boolean. IDs are generated by SQLite and cannot be set by request bodies.

Invalid input or malformed JSON returns 400. Missing todos, invalid IDs, and unknown
routes return 404. Bodies larger than 100 KB return 413. Errors have the shape
`{"error":"Todo not found"}`.

## Example requests (PowerShell)

```powershell
Invoke-RestMethod http://localhost:3000/todos

Invoke-RestMethod http://localhost:3000/todos -Method Post -ContentType 'application/json' -Body '{"title":"Test POST","completed":false}'

Invoke-RestMethod http://localhost:3000/todos/1 -Method Put -ContentType 'application/json' -Body '{"title":"Test PUT","completed":true}'

Invoke-RestMethod http://localhost:3000/todos/1 -Method Delete
```

Use `http://localhost:3000` as the base URL in C# tests while this app runs
in its own terminal.

## Adding posts and authentication later

- Add `src/modules/posts/` following the todo module, then mount its router in `src/app.js`.
- Add a numbered SQL migration such as `002_create_posts.sql`. Startup applies pending
  migrations once, in filename order, inside transactions. Add new migrations instead
  of editing ones that have already run.
- Add an auth module for login/logout and users. Shared authentication middleware can
  guard selected routers before their controllers run.
- Cookie sessions can use a SQLite-backed session store. API token authentication can
  be a separate middleware using the same user records. Add these when implementing
  authentication; current todo routes are public.

Tests use temporary databases and do not touch your practice data. They verify CRUD,
validation, SQL parameter binding, persistence after reopening, and migration behavior.
